## Phạm vi và hợp đồng

Tiền điều kiện: tài khoản đã đăng ký và xác minh email theo P1-01. Hồ sơ chờ duyệt = `email_verified` và (`not profile_approved` hoặc `cho_duyet_lai`). Duyệt chuyển `trang_thai_tai_khoan` `CHO_KICH_HOAT` → `HOAT_DONG`, cấp MEMBER qua `AuthService` (đọc trạng thái trực tiếp từ DB mỗi request).

| Endpoint | Input → output | Quyền |
|---|---|---|
| `GET /api/v1/profile/me` | → `{id,name,studentId,email,phone,school,campus,major,cohort,studyStatus,reputation,emailVerified,profileApproved,profileStatus,rejectReason,pendingUpdate,hasStudentCard,accountStatus,version}` | Bearer, mọi tài khoản đăng nhập |
| `PATCH /api/v1/profile/me` | `{name?,studentId?,phone?,school?,campus?,major?,cohort?,studyStatus?}` → hồ sơ mới. Chỉ `phone` lưu ngay; thay đổi định danh/học tập ghi vào bản chờ duyệt. `studyStatus` ∈ `DANG_HOC`/`DA_TOT_NGHIEP`, giá trị khác → 400 `INVALID_INPUT` | Bearer |
| `POST /api/v1/profile/me/student-card` | multipart `file` (JPEG/PNG, ≤ 5MB) → 204 | Bearer |
| `GET /api/v1/profile/student-cards/{userId}` | → bytes, `Content-Type` theo magic bytes, `Cache-Control: no-store` | Chủ sở hữu hoặc MODERATOR |
| `PATCH /api/v1/profile/email` | `{currentPassword,newEmail}` → `{challengeId,expiresIn,resendAfter,message}` | Bearer |
| `POST /api/v1/profile/email/verify` | `{challengeId,code}` → 204, cập nhật `email` + `email_verified` | Bearer |
| `GET /api/v1/admin/profiles/pending?offset&limit` | → `[{id,name,studentId,email,kind,submittedAt,hasStudentCard}]`, `kind` ∈ `DANG_KY`/`CAP_NHAT`, `limit` kẹp 1..100 | MODERATOR |
| `GET /api/v1/admin/profiles/{userId}` | → hồ sơ chờ duyệt (kèm giá trị đang chờ) | MODERATOR |
| `GET /api/v1/admin/profiles/{userId}/student-card` | → ảnh thẻ | MODERATOR |
| `POST /api/v1/admin/profiles/{userId}/approve` | query tuỳ chọn `?expectedVersion=` → 204; áp bản chờ duyệt, `profile_approved=true`, điểm 100 đúng một lần, ghi `kiem_duyet_ho_so`; lệch phiên bản → 409 `PROFILE_CHANGED` | MODERATOR |
| `POST /api/v1/admin/profiles/{userId}/reject` | body `{reason}` 3–1000 ký tự + query tuỳ chọn `?expectedVersion=` → 204; xóa bản chờ duyệt, ghi lý do + lịch sử, đẩy email vào outbox; lệch phiên bản → 409 `PROFILE_CHANGED` | MODERATOR |

Mã lỗi mới (giữ convention `{code,message}` của P1-01): `INVALID_PHONE`, `STUDENT_ID_IN_USE`, `INVALID_STUDENT_CARD`, `STUDENT_CARD_FORBIDDEN`, `STUDENT_CARD_NOT_FOUND`, `PROFILE_NOT_FOUND`, `EMAIL_NOT_VERIFIED`, `PROFILE_ALREADY_HANDLED`, `PROFILE_CHANGED`, `INVALID_REASON`, `EMAIL_UNCHANGED`, `EMAIL_IN_USE`. Dùng lại `INVALID_INPUT`, `INVALID_EMAIL`, `INVALID_OTP`, `INVALID_CREDENTIALS`, `RATE_LIMITED`.

Chống duyệt đè có hai lớp: (1) `approve`/`reject` khóa dòng `thanh_viens` (`for update`) rồi kiểm lại trạng thái chờ — kiểm duyệt viên thứ hai nhận 409 `PROFILE_ALREADY_HANDLED`; (2) `expectedVersion` lấy từ `version` của bản đã đọc — người dùng sửa hồ sơ sau khi kiểm duyệt viên mở trang thì quyết định bị từ chối với 409 `PROFILE_CHANGED`. Bỏ `expectedVersion` (client cũ) thì chỉ còn lớp 1.

`PATCH /api/v1/auth/profile` đã bị gỡ: mọi thay đổi định danh phải qua duyệt (UC-05).
