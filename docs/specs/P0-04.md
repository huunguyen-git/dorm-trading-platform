# P0-04 · Thiết lập CI Pipeline & Code Quality

| Phân công | Nội dung |
|---|---|
| Phase và mục tiêu | Phase 0 · Thiết lập CI pipeline tự động hóa kiểm thử mã nguồn, bảo vệ chất lượng repo và làm cổng kiểm duyệt cho main. Dòng task hạ tầng không gắn UC. |
| Phụ trách / review | Lê Vũ Hoàng Nguyên phụ trách CI pipeline và cấu hình kiểm tra chất lượng. Người review chưa được ghi trong roadmap. |

## Phạm vi bàn giao

P0-04 thiết lập toàn bộ quy trình CI/CD ban đầu cho kho lưu trữ trên GitHub Actions:
1. **Kiểm tra repo và mã nguồn (`repository` job):** Kiểm tra lỗi khoảng trắng dư thừa trên dải commit của PR bằng `git diff --check`, ngăn ngừa ký tự xung đột merge.
2. **Kiểm tra cú pháp workflow (`workflow-lint` job):** Lint toàn bộ các tệp workflow Actions bằng Docker `rhysd/actionlint:1.7.12` ở chế độ read-only.
3. **Biên dịch và kiểm thử Backend (`backend` job):** Tự động cài đặt Temurin JDK 21 LTS trên `ubuntu-latest`, bật cache Maven, cấp quyền thực thi cho Unix wrapper, chạy `./mvnw --batch-mode --no-transfer-progress clean verify` và lưu trữ báo cáo Surefire dưới dạng artifact.
4. **Cổng kiểm duyệt hợp nhất (`required` job):** Gom trạng thái của tất cả các job bắt buộc (`needs: [repository, workflow-lint, backend]`), kết xuất bảng Markdown trực quan vào GitHub Actions Step Summary.
5. **Cấu hình bảo mật và vệ sinh mã nguồn:** Thiết lập `.editorconfig` đồng bộ UTF-8/LF, `.github/dependabot.yml` tự động quét phụ thuộc Actions và Maven hàng tuần, và `.github/pull_request_template.md` chuẩn hóa biểu mẫu PR.

## Tiêu chí nghiệm thu

| Mục tiêu | Điều khoản | Tình huống đạt | Kết quả thực tế |
|---|---|---|---|
| Kiểm tra khoảng trắng repo | P0-04 · chất lượng repo | PR dính lỗi trailing whitespace hoặc conflict marker bị chặn; PR sạch thì pass. | Đạt. `git diff --check` bắt chính xác lỗi vi phạm. |
| Cú pháp Actions | P0-04 · kiểm thử workflow | Toàn bộ tệp `.github/workflows/*.yml` hợp lệ cú pháp, không có thuộc tính sai. | Đạt. `actionlint` chạy trên Docker phân tích sạch cú pháp và ngữ cảnh GitHub Actions. |
| Kiểm thử Backend tự động | P0-04 · tích hợp P0-01 | Runner `ubuntu-latest` cài Temurin JDK 21, cache Maven, chạy `./mvnw clean verify` đạt 4/4 test HTTP bảo mật, sinh artifact báo cáo. | Đạt. Bộ test của P0-01 hoàn tất thành công trong 10-15s khi có cache. Artifact Surefire được lưu giữ. |
| Cổng Branch Protection | P0-04 · cổng hợp nhất | Chỉ cần cấu hình 1 check duy nhất `required` cho nhánh `main`. Nếu bất kỳ job nào fail, `required` fail và chặn merge. | Đạt. Script Python trong `required` job đánh giá đúng kết quả tất cả các `needs` và render bảng Step Summary. |

## Hướng dẫn chạy thử và kiểm tra cục bộ

```bash
# 1. Kiểm tra lỗi khoảng trắng trước khi commit
git diff --check

# 2. Kiểm thử Backend cục bộ
cd backend
.\mvnw.cmd clean verify   # Trên Windows
./mvnw clean verify       # Trên Linux / macOS
```

## Hướng dẫn tích hợp tiếp theo

| Task nhận | Phần cần thực hiện | Cách kiểm tra khi tích hợp |
|---|---|---|
| P0-02 · Mobile và Web | Khi hoàn tất bàn giao `package-lock.json` và script test/lint của `admin-web/` và `mobile/`, thêm job tương ứng vào `ci.yml` dùng Node 24 LTS. | Thêm `admin-web` và `mobile` vào danh sách `needs` của `required`. |
| P0-03 · Docker & DB | Khi có Testcontainers và PostgreSQL, cấu hình runner Docker thực thi integration test backend với database container. | Mở rộng job `backend` hoặc thêm job `integration-test` chạy container kiểm thử. |
| Quản trị viên repo | Cấu hình GitHub Branch Protection Rule cho nhánh `main`. | Bật "Require status checks to pass before merging" và chọn duy nhất check `required`. |
