## Phạm vi bàn giao

P0-01 dựng `backend/` trong monorepo, khóa phiên bản Java, Spring Boot và Maven Wrapper, tổ chức sáu package miền, cung cấp API health và khung xác thực JWT/RBAC dùng chung. P0-02 tạo hai thư mục client cùng UI Kit. P0-03 tạo thư mục hạ tầng và tích hợp PostgreSQL. Cấu trúc đầy đủ của Phase 0 được thể hiện trong [kiến trúc mục tiêu](../01-architecture.md).

## Manual test trên Windows

### Cửa sổ PowerShell 1 · Chạy backend

Mở PowerShell tại thư mục gốc repo, chạy `cd backend`. Nếu đang ở `backend` thì bắt đầu ngay với bước 1. Cần Temurin JDK 21. Lần build đầu cần Internet để Maven tải dependency.

1. Kiểm tra Java trong **chính cửa sổ sẽ chạy backend**.

   ```powershell
   & "$env:JAVA_HOME\bin\java.exe" -version
   ```

   Kết quả cần có phiên bản `21`. Nếu PowerShell báo không tìm thấy `\bin\java.exe`, hãy đặt `$env:JAVA_HOME = 'C:\duong-dan-den-jdk-21'` rồi chạy lại. Thay đường dẫn ví dụ bằng thư mục JDK thật trên máy, nơi có `bin\java.exe`. Giữ dấu `&` trước đường dẫn có ngoặc kép để PowerShell thực thi lệnh.

2. Nếu JAR từ lần thử trước đang chạy, nhấn `Ctrl+C` trong cửa sổ đang chạy JAR rồi mới đóng gói lại. Windows giữ khóa file khi JAR đang mở, khiến Maven báo `Failed to delete ...jar` ở bước clean.

   ```powershell
   .\mvnw.cmd clean package
   ```

   Chỉ tiếp tục khi thấy `BUILD SUCCESS` và 4 test đạt. Dùng JAR cho bài thử này vì đã tái hiện `ClassNotFoundException` với `spring-boot:run` khi đường dẫn repo trên Windows có dấu tiếng Việt. Chạy lại bước đóng gói sau khi sửa mã.

3. Tạo khóa dùng cho phiên thử và chạy JAR. Giữ cửa sổ mở khi thấy `Started DormTradingApplication`. Các lệnh bên dưới dùng cổng mặc định 8082. Nếu đã đặt `SERVER_PORT`, dùng cổng ghi trong log Tomcat.

   ```powershell
   $key = New-Object byte[] 32
   $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
   $rng.GetBytes($key)
   $rng.Dispose()
   $env:JWT_SECRET = [Convert]::ToBase64String($key)
   & "$env:JAVA_HOME\bin\java.exe" -jar .\target\backend-0.0.1-SNAPSHOT.jar
   ```

### Cửa sổ PowerShell 2 · Gửi request

Mở cửa sổ mới ở thư mục bất kỳ. Dùng nguyên URL trong từng lệnh. Biến PowerShell như `$api` chỉ có giá trị trong cửa sổ đã gán nó. Khi biến rỗng, curl chỉ nhận đường dẫn và báo `No host part in the URL`.

| Ca thử | Lệnh PowerShell | Kết quả mong đợi |
|---|---|---|
| Backend đang phục vụ | `curl.exe -i http://localhost:8082/api/v1/health` | HTTP 200, JSON có `status=UP`, `service=dorm-trading-backend` và `timestamp`. |
| Thiếu token | `curl.exe -i http://localhost:8082/api/v1/admin/probe` | HTTP 401, có header `WWW-Authenticate: Bearer`. |
| Token sai định dạng | `curl.exe -i -H "Authorization: Bearer invalid-token" http://localhost:8082/api/v1/admin/probe` | HTTP 401. |
| Preflight từ web Vite | `curl.exe -i -X OPTIONS http://localhost:8082/api/v1/admin/probe -H "Origin: http://localhost:5173" -H "Access-Control-Request-Method: GET" -H "Access-Control-Request-Headers: Authorization"` | Với CORS mặc định, HTTP 200, `Access-Control-Allow-Origin` khớp origin và `Access-Control-Allow-Headers` chứa `Authorization`. Đổi origin thành `http://localhost:9999` và chạy lại, mong đợi 403. |

Hai ca 401 kiểm tra bộ lọc JWT của JAR. Controller `/api/v1/admin/probe` chỉ tồn tại trong bộ test. Để kiểm tra phân quyền với token hợp lệ, nhấn `Ctrl+C` ở **cửa sổ 1** để dừng JAR rồi chạy ca tự động sau ngay tại đó. Ca này tự gửi hai request, kiểm tra `MEMBER` nhận 403 và `ADMIN` nhận 200. Kết quả đạt là 1 test, 0 lỗi.

```powershell
.\mvnw.cmd "-Dtest=ApiSecurityTest#requiresAdminRole" test
```
