## Phạm vi và hợp đồng

Đầu vào là `main` đã đồng bộ `origin/main`, cây làm việc sạch trước khi tạo branch. Branch `task/p0-06-conventions-pipeline` đã được người dùng xác nhận trước khi tạo; đây là ngoại lệ tên branch cho phiên này so với mẫu `<type>/<mã-task>-<slug>` của P0-05, không thay đổi quy ước chung.

Đầu ra đạt yêu cầu là một hướng dẫn thống nhất có thể làm lại từ bản clone mới, một PR mẫu có liên kết run và artifact CI, cùng bảng xác nhận của từng thành viên trên cùng revision nghiệm thu. Chỉ ghi đạt khi có kết quả thật; kết quả P0-02/03/04 là đầu vào tham khảo, không thay thế lượt nghiệm thu P0-06.

Không triển khai nghiệp vụ Phase 1, đổi cấu trúc Maven, nâng stack, sửa schema hoặc xử lý toàn bộ tồn đọng P0-03 trong task này. Luồng đăng nhập/duyệt/kho với API thật tiếp tục thuộc các task Phase 1. Mobile export Android là phép kiểm tra build, chưa phải APK hay bằng chứng chạy thiết bị.

### Checklist chạy lại dự kiến

1. Clone vào thư mục mới, checkout revision nghiệm thu; ghi phiên bản công cụ. Chuẩn bị `.env` từ các file mẫu ở root và từng client, không ghi đè cấu hình riêng đã có. Cấp `JWT_SECRET` thử riêng cho backend theo hướng dẫn P0-01.
2. Kiểm tra Compose và khởi động PostgreSQL, Maildev, MinIO theo P0-03. Xác nhận HTTP của Maildev/MinIO trực tiếp; chưa dùng healthcheck hiện có làm bằng chứng duy nhất. Không xóa volume hay dữ liệu có sẵn để chạy thử.
3. Trong `backend/`, chạy Maven Wrapper `clean verify` trên Java 21 với Docker hoạt động cho Testcontainers. Ghi số test thực tế, failure/error/skipped và báo cáo Surefire; mốc tham khảo P0-03 là 7 test, không bỏ qua integration test để lấy kết quả xanh.
4. Trong từng `admin-web/` và `mobile/`, chạy `npm ci`, `npm run lint`, `npm test`, `npm run build` trên Node 24. Ghi mã thoát và báo cáo; mốc tham khảo P0-02 là 5 test mỗi client. `lint` hiện chỉ là TypeScript, không ghi thành đã có ESLint.
5. Khởi động backend, web Vite và Expo. Xác nhận UI khởi động; kiểm tra `/api/v1/health` từ origin web và từ giả lập/thiết bị mobile đến cùng backend. Lưu URL đã dùng, HTTP status và response hoặc lỗi mạng; tách bằng chứng kết nối khỏi test dùng mock. Ghi cách kiểm tra cụ thể và giới hạn nếu dùng công cụ mạng ở môi trường client; không coi đó là luồng nghiệp vụ trong app đã tích hợp.
6. Với PR mẫu, đối chiếu revision chạy CI và local; lưu kết quả run cuối, Step Summary của `required` và artifact. Nếu thay đổi revision sau khi thu bằng chứng, ghi các phần cần chạy lại và người xác nhận.
